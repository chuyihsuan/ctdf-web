# CTDF 第一版無資料庫後台流程

完整的角色權責、上架、修改、下架、緊急處理與驗收步驟，請參閱 `docs/CONTENT_PUBLISHING_MANUAL.md`。

## 定位

第一版後台是一個可部署於網站的靜態內容製作工具，不使用內容資料庫，也不會直接連接 GitHub。管理者在瀏覽器建立與預覽內容，核准後匯出 ZIP 上架包，再由技術人員以 Git 分支與 Pull Request 上架。

## 資料保存

- 草稿文字、狀態、圖片與附件保存在目前瀏覽器的 IndexedDB。
- 資料不會在不同電腦或瀏覽器之間同步。
- 清除網站資料可能刪除草稿，重要內容應定期匯出 ZIP 備份。
- 後台不保存 GitHub、Vercel 或其他平台的 Token。

## 登入保護

`/admin/login/` 的帳密只用於操作介面 Demo，不能視為正式安全機制。正式部署時，必須在網站入口層加入帳號驗證，並以 HTTPS 提供後台服務。

## 內容流程

1. 秘書長登入後台。
2. 建立或修改公告、賽事、影音、文件或固定頁面。
3. 儲存草稿至 IndexedDB。
4. 使用前台版型預覽。
5. 將內容標記為待審核。
6. 確認內容與公開授權後，按「核准並匯出 ZIP」。
7. 將 ZIP 上架包交給副秘書長。
8. 副秘書長檢查 `manifest.json`、內容、圖片與附件。
9. 以獨立 Git 分支提交，先部署至固定 Demo 環境上板 Review。
10. 秘書長確認 Demo 並留下「同意發布正式版」紀錄。
11. 副秘書長確認核准版本沒有變動後，才合併至 `main` 並發布正式環境。
12. 正式部署完成後，再由秘書長與副秘書長分別完成內容及技術驗收。

## ZIP 上架包

```text
manifest.json
content/<module>/<content-id>.json
uploads/<files>
README.txt
```

`manifest.json` 包含上架編號、內容模組、新增或修改、標題、核准狀態、匯出時間與附件清單。後台只接受自己產生的無壓縮 ZIP 上架包，匯入後一律還原為草稿，避免未經確認直接發布。

## 已知限制

- 不支援多人共同編輯。
- 不支援跨裝置草稿同步。
- 不會直接更新正式網站。
- 登入 Demo 不取代正式入口層驗證。
- 技術人員仍需檢查上架包並完成 GitHub 上架流程。
